# 12. Ohjelman analyysi

{: .code-title }
collatz.c
```c
#include <stdio.h>

#define N 10000000

int collatz(long n) {
    int steps = 1;
    while (n != 1) {
        steps++;
        if (n % 2 == 0) {
            n = n / 2;
        } else {
            n = 3 * n + 1;
        }
    }
    return steps;
}

int main(void) {
    long total = 0;
    for (int i = 1; i <= N; i++) {
        total += collatz(i);
    }
    printf("%ld\n", total);
}
```

Komento `endbr64` aliohjelmien alussa on tietoturvaan liittyvä komento, joka määrittelee, että kyseinen kohta koodissa on aliohjelman alku, jonne saa hypätä muualta koodista epäsuoran osoituksen kautta. TODO: tarkemmin

Molemmat aliohjelmat lisäävät tavallisen käytännön mukaisesti alussa rekisterin `rbp` sisällön pinoon ja palauttavat sen lopuksi pinosta.

Aliohjelma `main` varaa pinosta 16 tavua tilaa muuttujille:

- Muuttuja `total` on muistissa osoitteessa `rbp - 8`
- Muuttuja `i` on muistissa osoitteessa `rbp - 12`

Aliohjelman lopussa on komento `leave`, joka on lyhyempi vastine seuraaville komennoille, jotka palauttavat pinorekisterien tilan ennalleen:

### Collatz-jonon laskenta

Aliohjelma `collatz` laskee Collatz-jonon pituuden annetulle parametrille. Pinon käsittely on toteutettu eri tavalla kuin aliohjelmassa `main`: aliohjelma säilyttää pinossa paikallisia muuttujia, mutta se _ei_ muuta pinorekisterin `rsp` arvoa.

Tämä perustuu siihen, että pinossa rekisterin `rsp` alapuolella on 128 tavun kokoinen _punainen alue_ (_red zone_), jossa olevaa muistia aliohjelman on sallittua käyttää muuttamatta rekisterin `rsp` arvoa. Tämä tehostaa koodia, koska ei tarvita komentoja, jotka muuttavat rekisterin `rsp` arvoa.

Seuraava koodi vastaa parillisuustarkastusta `n % 2 == 0`:

```nasm
	andl	$1, %eax
	testq	%rax, %rax
	jne	.L3
```

Tarkastus perustuu siihen, että luku on parillinen tarkalleen silloin, kun sen viimeinen bitti on 0. Koodi suorittaa and-operaation, jonka seurauksena rekisterin `eax` sisältö on joko 0 (parillinen) tai 1 (pariton). Koodi hyppää nimiöön `.L3`, jos rekisterin `rax` sisältö ei ole 0 eli luku on pariton.

Seuraava koodi vastaa lauseketta `n = n / 2`, joka jakaa luvun kahdella. Koodin alussa rekisteri `rax` sisältää muuttujan `n` arvon.

```nasm
	movq	%rax, %rdx
	shrq	$63, %rdx
	addq	%rdx, %rax
	sarq	%rax
```

Koodi suorittaa bittisiirron oikealle, joka on tehokas tapa jakaa luku kahdella. Koodissa on kuitenkin monimutkaisuutta sen takia, että se ottaa huomioon tilanteen, jossa luku `n` on negatiivinen.

C-kielessä lausekkeen `n / 2` arvo pyöristyy ylöspäin, jos luku `n` on negatiivinen pariton luku. Esimerkiksi lausekkeen `-5 / 2` arvo on `-2`. Kuitenkin aritmeettinen bittisiirto `sar` pyöristäisi luvun alaspäin, minkä takia koodi toimii seuraavasti:

- Koodi laittaa ensin bittisiirron avulla rekisterin `rdx` sisällöksi rekisterin `rax` luvun etumerkin (0 = positiivinen, 1 = negatiivinen). Koska luvussa on 64 bittiä, koodi siirtää bittejä 63 askelta oikealle.

- Tämän jälkeen koodi lisää rekisterissä `rdx` olevan etumerkin rekisterin `rax` arvoon eli käytännössä säilyttää positiivisen luvun entisellään ja kasvattaa negatiivista lukua yhdellä.

- Lopuksi koodi suorittaa aritmeettisen bittisiirron (`sar`), joka jakaa luvun kahdella ja antaa nyt C-kielen toimintaa vastaavan tuloksen myös negatiiviselle parittomalle luvulle.

<div class="note" markdown="1">
Tässä tapauksessa on oikeastaan tarpeetonta varautua negatiiviseen parittomaan lukuun, koska jako kahdella tehdään vain siinä tapauksessa, että luku on parillinen. Tässä kääntäjä ei ole hyödyntänyt tietoa siitä, että edeltävässä koodissa on varmistettu luvun olevan parillinen.

Sen sijaan on mahdollista, että luku on negatiivinen, koska suurella parametrin `n` arvolla Collatzin lukujonossa saattaa olla niin suuri luku, ettei se mahdu 64-bittiseen `long`-muuttujaan ja luvusta tulee negatiivinen ylivuodon seurauksena.
</div>
