# 6. Tiedostot

## Tiedostojen käsittely

C-kielen standardikirjaston tiedosto `stdio.h` sisältää funktioita tiedostojen käsittelyyn. Tavallisesti tiedoston käsittely etenee seuraavasti:

1. Tiedosto avataan funktiolla `fopen` käsittelyä varten. Funktiolle annetaan tiedoston nimi sekä avaustapa.
2. Tiedostoon kirjoitetaan tietoa tai siitä luetaan tietoa standardikirjaston funktioilla.
3. Tiedosto suljetaan funktiolla `fclose`, joka lopettaa tiedoston käsittelyn.

### Kirjoitus ja lukeminen

Seuraava koodi luo tiedoston `numbers.txt` ja kirjoittaa siihen tietoa:

```c
FILE *file = fopen("numbers.txt", "w");

int n = 10;
fprintf(file, "%d\n", n);

for (int i = 1; i <= n; i++) {
    fprintf(file, "%d ", i * i);
}
fprintf(file, "\n");

fclose(file);
```

Koodin tuloksena syntyy seuraava tiedosto `numbers.txt`:

```
10
1 4 9 16 25 36 49 64 81 100
```

Koodi toimii seuraavasti:

- Funktio `fopen` avaa tiedoston ja palauttaa `FILE*`-tyyppisen osoittimen, jonka kautta tiedostoa voidaan käsitellä.
- Avaustapa `"w"` tarkoittaa, että tiedosto avataan kirjoittamista varten.
- Muuttuja `file` sisältää osoittimen avattuun tiedostoon. Tämän osoittimen avulla avattuun tiedostoon viitataan muissa funktiokutsuissa.
- Funktio `fprintf` kirjoittaa tiedostoon tietoa samaan tapaan kuin funktio `printf` tulostaa tietoa käyttäjälle.
- Funktio `fclose` sulkee tiedoston käsittelyn lopuksi.

<div class="note" markdown="1">
Avaustavassa `"w"` funktio `fopen` luo uuden tiedoston, jos tiedostoa ei ole olemassa. Jos kuitenkin tiedosto on olemassa, tiedoston sisältö tyhjentyy avaamisen yhteydessä.

Jos mahdollista olemassa olevaa tiedostoa ei haluta tyhjentää, voidaan käyttää avaustapaa `"a"`. Tässä tapauksessa tietoa kirjoitetaan tiedoston olemassa olevan sisällön perään.
</div>

Seuraava koodi lukee vastaavasti tiedoston `numbers.txt` sisällön:

```c
FILE *file = fopen("numbers.txt", "r");

int n;
fscanf(file, "%d", &n);

int sum = 0;
for (int i = 0; i < n; i++) {
    fscanf(file, "%d", &number);
    sum += number;
}
printf("%d\n", sum); // 385

fclose(file);
```

Koodi lukee tiedostosta ensin lukujen määrän ja sitten kunkin luvun yksitellen. Koodi laskee tiedostosta luettujen lukujen summan ja tulostaa sen.

Avaustapa `"r"` tarkoittaa, että tiedostosta luetaan tietoa. Tietoa luetaan funktiolla `fscanf`, joka toimii vastaavasti kuin käyttäjän syötettä lukeva funktio `scanf`.

<div class="note" markdown="1">
Tiedoston lukemisessa `fscanf`-funktiolla on kätevää, että luettavat tiedot voi erotella vapaasti tyhjän tilan avulla. Esimerkiksi yllä oleva koodi pystyy lukemaan myös seuraavassa muodossa olevan tiedoston:

```
3
42
5
1337
```

Tässä tiedosto sisältää luvut 42, 5 ja 1337 rivinvaihdoin eroteltuina.
</div>

### Rivien lukeminen

Tarkastellaan seuraavaksi tiedostoa `aybabtu.txt`:

```
Operator: Main screen turn on.
Captain: It's you !!
CATS: How are you gentlemen !!
CATS: All your base are belong to us.
```

Seuraava koodi lukee ja näyttää tiedoston rivien sisällön:

```c
FILE *file = fopen("aybabtu.txt", "r");

char buffer[128];
int count = 0;

while (fgets(buffer, sizeof(buffer), file) != NULL) {
    count++;
    printf("%d: %s", count, buffer);
}

fclose(file);
```

Koodi tulostaa tiedoston sisällön näin:

```
1: Operator: Main screen turn on.
2: Captain: It's you !!
3: CATS: How are you gentlemen !!
4: CATS: All your base are belong to us.
```

Tässä käytössä on funktio `fgets`, joka lukee rivin tiedostosta. Funktiolle annetaan osoitin muistialueeseen, luettavan tiedon maksimimäärä tavuina (mukaan lukien merkkijonon nollatavu) sekä tiedosto-osoitin. Kun tiedosto on luettu loppuun, funktio palauttaa `NULL`-osoittimen ja silmukka päättyy.

<div class="note" markdown="1">
Tässä koodissa oletuksena on, että rivin pituus on enintään 128 tavua. Jos rivi on pidempi, funktio `fgets` lukee rivin useassa osassa.

Voimme tutkia asiaa muuttamalla taulukon `buffer` kokoa. Esimerkiksi jos kooksi muutetaan 8, koodin tulostus on seuraava:

```
1: Operato2: r: Main3:  screen4:  turn o5: n.
6: Captain7: : It's 8: you !!
9: CATS: H10: ow are 11: you gen12: tlemen 13: !!
14: CATS: A15: ll your16:  base a17: re belo18: ng to u19: s.
```

Tässä jokainen `fgets`-kutsu lukee joko riviä eteenpäin 7 merkkiä tai rivin loppuun asti, riippuen kumpi tulee vastaan aiemmin.
</div>

### Virhetilanteet

Tiedostojen käsittelyssä voi esiintyä erilaisia virhetilanteita, kuten että ohjelma yrittää lukea tietoa tiedostosta, jota ei ole olemassa. Tällaisia tilanteita voi havaita tutkimalla tiedostofunktioiden palautusarvoja.

Funktio `fopen` palauttaa tiedosto-osoittimen sijasta arvon `NULL`, jos tiedoston avaaminen ei onnistunut. Seuraava koodi käsittelee tilanteen:

```c
FILE *file = fopen("test.txt", "r");
if (file == NULL) {
    printf("Can't read the file\n");
}
```

## Tietovirrat

<div class="note" markdown="1">
Funktio `fgets` on kätevä funktio rivin lukemiseen, jonka käyttäminen on turvallista, kun funktiolle annettava muistialueen koko on sama kuin varattu taulukon koko. Tällöin ei ole puskuriylivuodon riskiä, koska tiedostossa oleva pitkä rivi ei voi mennä varatun muistialueen ulkopuolelle.

Funktiota voi käyttää myös rivin lukemiseen käyttäjältä seuraavasti:

```c
fgets(buffer, 128, stdin);
```

Tässä `stdin` on erityinen "tiedosto", joka viittaa standardisyötteeseen (standard input) eli oletuksena käyttäjältä tulevaan tietoon.
</div>

## Tiedoston tavusisältö

Jokaisen tiedoston sisältö matalalla tasolla on jono peräkkäisiä tavuja. Tiedoston formaatista riippuu, miten nämä tavut tulkitaan.

Tarkastellaan esimerkiksi seuraavaa tiedostoa `aybabtu.txt`:

```
Operator: Main screen turn on.
Captain: It's you !!
CATS: How are you gentlemen !!
CATS: All your base are belong to us.
```

Tämä tiedosto on _tekstitiedosto_, mikä tarkoittaa, että tiedostossa on rivejä, jotka muodostuvat merkeistä. Voimme tutkia Linuxissa tiedoston sisältöä tavumuodossa esimerkiksi `xxd`-komennolla:

```console
$ xxd aybabtu.txt
00000000: 4f70 6572 6174 6f72 3a20 4d61 696e 2073  Operator: Main s
00000010: 6372 6565 6e20 7475 726e 206f 6e2e 0a43  creen turn on..C
00000020: 6170 7461 696e 3a20 4974 2773 2079 6f75  aptain: It's you
00000030: 2021 210a 4341 5453 3a20 486f 7720 6172   !!.CATS: How ar
00000040: 6520 796f 7520 6765 6e74 6c65 6d65 6e20  e you gentlemen
00000050: 2121 0a43 4154 533a 2041 6c6c 2079 6f75  !!.CATS: All you
00000060: 7220 6261 7365 2061 7265 2062 656c 6f6e  r base are belon
00000070: 6720 746f 2075 732e 0a                   g to us..                                  ..
```

Komento näyttää tiedoston sisällön tavuina heksamuodossa ja lisäksi tavuja vastaavat merkit niistä tavuista, joilla on merkkiesitys. Tiedosto alkaa seuraavasti:

- Ensimmäinen tavu `4f` vastaa merkkiä `O`.
- Toinen tavu `70` vastaa merkkiä `p`.
- Kolmas tavu `65` vastaa merkkiä `e`.

Tavu `0a` tarkoittaa tiedostossa olevaa rivinvaihtoa. Tällä tavulla ei ole merkkiesitystä, vaan sen kohdalla on merkki `.` komennon tulostuksessa.

<div class="note" markdown="1">
Tavu `0a` on Unix-rivinvaihto, joka on käytössä esimerkiksi Linuxissa ja Macissa. Sen sijaan Windowsissa rivinvaihto ilmaistaan tavallisesti kahden tavun `0d` ja `0a` yhdistelmänä. Tässä on taustalla mekaanisen kirjoituskoneen toiminta: tavu `0d` (_carriage return_) siirtää kirjoituskohdan vasempaan reunaan ja tavu `0a` (_line feed_) siirtää paperia ylöspäin seuraavalle riville.
</div>

### Tavujen lukeminen

Seuraava koodi lukee tiedoston sisällön 16 tavun osissa ja tulostaa kunkin osan tavut heksamuodossa:

```c
FILE *file = fopen("aybabtu.txt", "rb");

char buffer[16];
int len;

while (len = fread(buffer, 1, 16, file)) {
    for (int i = 0; i < len; i++) {
        printf("%02x ", buffer[i]);
    }
    printf("\n");
}

fclose(file);
```

Koodi tulostaa tiedoston sisällön näin:

```console
4f 70 65 72 61 74 6f 72 3a 20 4d 61 69 6e 20 73
63 72 65 65 6e 20 74 75 72 6e 20 6f 6e 2e 0a 43
61 70 74 61 69 6e 3a 20 49 74 27 73 20 79 6f 75
20 21 21 0a 43 41 54 53 3a 20 48 6f 77 20 61 72
65 20 79 6f 75 20 67 65 6e 74 6c 65 6d 65 6e 20
21 21 0a 43 41 54 53 3a 20 41 6c 6c 20 79 6f 75
72 20 62 61 73 65 20 61 72 65 20 62 65 6c 6f 6e
67 20 74 6f 20 75 73 2e 0a
```

Koodin toiminta on seuraava:

- Funktiolle `fopen` annetaan parametri `"rb"`, mikä tarkoittaa, että tiedosto avataan binäärimuodossa lukemista varten.
- Taulukko `buffer` sisältää tiedostosta kerrallaan luetut tavut.
- Funktio `fread` lukee tietoa tiedostosta. Funktion parametrit ovat osoitin puskuriin, yhden tietoyksikön koko (tässä 1 eli yksi tavu), tietoyksiköiden määrä (tässä 16) ja tiedosto-osoitin.
- Funktion `fread` palautusarvo on luettujen tietoyksiköiden määrä. Kun määrä on 0, tiedosto päättyi tai tapahtui virhe.
- Tässä `while`-silmukka on rakennettu niin, että silmukka jatkuu niin kauan kuin tiedostosta saadaan luettua tietoa.
- Funktiossa `printf` merkintä `%02x` tarkoittaa, että tavun arvo tulostetaan heksamuodossa kahtena merkkinä.

### Tavujen kirjoitus

Vastaavasti funktio `fwrite` kirjoittaa tavuja tiedostoon. Esimerkiksi seuraava koodi kirjoittaa tiedostoon `int`-muuttujan ja merkkijonon sisällön.

```c
int number = 42;
char word[] = "saippuakauppias";

FILE *file = fopen("test.bin", "wb");
fwrite(&number, sizeof(number), 1, file);
fwrite(word, sizeof(word), 1, file);
fclose(file);
```

Koodi tuottaa tiedoston `test.bin`, jonka sisältö on seuraava:

```console
$ xxd test.bin
00000000: 2a00 0000 7361 6970 7075 616b 6175 7070  *...saippuakaupp
00000010: 6961 7300                                ias.
```

Tiedostossa on ensin neljästä tavusta muodostuva `int`-luku, jonka tavut ovat `2a 00 00 00`. Luvun tavut on esitetty little endian -muodossa samalla tavalla kuin tietokoneen muistissa. Tämän jälkeen tiedostossa on merkkijonon sisältö, mukaan lukien merkkijonon lopussa oleva nollatavu.

<div class="note" markdown="1">
Tässä tapauksessa luku 42 vie tiedostossa enemmän tilaa binäärimuodossa kuin vastaavan luvun esitys merkkimuodossa. Luku vie tilaa `int`-tyyppisenä neljä tavua, mutta sen voisi esittää merkkijonona kahtena tavuna.

Tilanne kuitenkin muuttuisi, jos luku olisi suurempi. Esimerkiksi luku 123456789 vie tilaa tekstimuodossa yhdeksän tavua mutta binäärimuodossa tilaa kuluu edelleen neljä tavua `int`-tyyppisenä lukuna.
</div>

## Kuvatiedoston käsittely

Katsotaan seuraavaksi tarkemmin, miten kuvan sisältö voidaan tallentaa tiedostoon ja miten tiedosto voidaan tulkita C-kielellä.

Tutustumme PCX-formaattiin, jossa kuvan sisältö tallennetaan pikseliriveinä. Jokaisen kuvan rivin sisältö on pakattu RLE-koodauksen avulla, jossa toistuvat tavut esitetään lyhennysmerkinnän avulla. Tämän ansiosta kuvan tiedostokoko saadaan pienemmäksi, jos riveillä on sopivalla tavalla toistuvia osuuksia.

<div class="note" markdown="1">
PCX on yksinkertainen kuvaformaatti, jota käytettiin erityisesti 1980- ja 1990-luvuilla. Se soveltuu hyvin kurssin esimerkiksi siitä, millaista tietoa kuvatiedoston sisällä voi olla ja miten tietoa kuvan pikseleistä voidaan pakata.

Nykyään samaan tarkoitukseen käytetään usein PNG-formaattia, joka on huomattavasti monimutkaisempi. PNG-formaatin etuna on, että käytössä on parempi pakkausalgoritmi ja kuvatiedoston koko on yleensä pienempi.
</div>

Tavoitteemme on tehdä C-ohjelma, joka näyttää annetun mustavalkoisen PCX-kuvan sisällön tekstimuodossa. Ohjelman tulee tarkastaa, että kuvan formaatti on oikea, selvittää kuvan leveys ja korkeus sekä hakea kuvan pikselien värit.

Jotta pystymme tulkitsemaan PCX-formaatissa olevan kuvan sisällön, meidän täytyy tietää, miten tiedosto rakentuu. Hyvää tietoa asiasta löytyy [sivuston FileFormat.Info kuvauksesta](https://www.fileformat.info/format/pcx/egff.htm), joka antaa riittävät ohjeet PCX-formaatin käsittelemiseen.

### PCX-tiedoston rakenne

PCX-tiedoston alussa on 128 tavun pituinen alkuosa (_header_), joka antaa yleiskuvan tiedoston sisällöstä. Alkuosan rakenne on seuraava:

Koko tavuina | Kentän kuvaus
--- | ---
1 | PCX-tiedoston tunniste (aina tavu `0a`)
1 | Tiedostoformaatin versio
1 | Kuvadatan koodaustapa (aina 1 = RLE)
1 | Bittien määrä pikseliä kohden
2 | Pienin x-koordinaatti
2 | Pienin y-koordinaatti
2 | Suurin x-koordinaatti
2 | Suurin y-koordinaatti
2 | Vaakasuuntainen resoluutio
2 | Pystysuuntainen resoluutio
48 | EGA-väripaletti
1 | Varattu alue (aina 0)
1 | Bittitasojen määrä
2 | Tavujen määrä kuvan rivillä
2 | Paletin tyyppi
2 | Vaakasuuntainen näytön koko
2 | Pystysuuntainen näytön koko
54 | Varattu alue (aina 0)

Tässä meidän kannaltamme oleellisia kenttiä ovat:

- Tiedoston alussa on aina tunnisteena tavu `0a`. Tämä on hyvä tarkastaa, koska jos tiedoston alussa on jokin muu tavu, tiedosto ei selvästi ole PCX-tiedosto.
- Bittien määrä pikseliä kohden ja bittitasojen määrä kertovat yhdessä, montako väriä kuvassa voi olla. Oletamme, että kuva on mustavalkoinen, jolloin kummankin kentän arvona tulee olla 1.
- Kuvan leveys ja korkeus selviävät x- ja y-koordinaattien rajoista.
- Tavujen määrä kuvan rivillä kertoo, montako tavua kuvadataa tulee lukea kullakin kuvan rivillä.

<div class="note" markdown="1">
Usein tiedoston sisällön tulkinnassa riittää tarkastella vain osaa kentistä. Esimerkiksi kuvadatan koodaustapa ei ole oleellinen kenttä, koska tämän kentän sisältönä on aina 1, joka tarkoittaa PCX-tiedoston RLE-koodausta.

Tiedostoformaatin suunnittelussa varaudutaan usein siihen, että formaatti saattaa laajentua tulevaisuudessa. PCX-formaattiin olisi _voinut_ tulla jokin toinen koodaustapa RLE-koodauksen lisäksi, mutta sellaista ei koskaan tullut.
</div>

Alkuosan jälkeen tiedostossa on kuvadata, joka esittää kuvan pikselit rivi kerrallaan RLE-koodattuna. Koodauksen ideana on, että jos rivillä on peräkkäin useita samanlaisia tavuja, ne voidaan esittää lyhyemmin muodossa "toista _n_ kertaa tavua _x_".

Kuvadatassa oleva tavu tulkitaan joko toistomerkintänä tai kuvan pikseleitä esittävänä tavuna. Jos tavun kaksi ensimmäistä bittiä ovat ykkösbittejä, kyseessä on toistomerkintä, jossa tavun muut bitit ilmaisevat toistokertojen määrän. Tällöin seuraava bitti on toistettava kuvan pikseleitä esittävä tavu. Muussa tapauksessa tavu tulkitaan sellaisenaan kuvan pikseleitä esittävänä tavuna.

Tarkastellaan esimerkkinä tavujonoa `91 c4 a5`:

- Ensimmäinen tavu `91` on bittimuodossa `01011011`. Tässä kaksi ensimmäistä bittiä eivät ole ykkösbittejä, joten tavu esittää kuvan pikseleitä.
- Toinen tavu `c4` on bittimuodossa `11000100`. Tässä kaksi ensimmäistä bittiä ovat ykkösbittejä, joten tavu on toistomerkintä. Toistokertojen määrä on bittimuodossa `000100` eli seuraavaa tavua toistetaan 4 kertaa.
- Kolmas tavu `a5` on bittimuodossa `10100101`. Tätä tavua toistetaan 4 kertaa edeltävän toistomerkinnän takia.
- Koko tavujonon tulkinta on siis `01011011 10100101 10100101 10100101 10100101`.

Tästä voidaan havaita seuraavia asioita:

- Bittien määrä pikseliä kohden on 1 (`01`) ja samoin bittitasojen määrä on 1 (`01`), joten kuva on mustavalkoinen kuva.
- Kuvan leveys on 64 pikseliä, koska pienin x-koordinaatti on 0 (`00 00`) ja suurin x-koordinaatti on 63 (`3f 00`).

- Jokainen kuvan rivi muodostuu 8 tavusta pikselitietoa (`08`).

Tarkastellaan sitten tavujonoa `c1 c0 c2 00 c2 01 81 c2 ff`, joka esittää kuvan ensimmäisen rivin pikselit. Tämän tavujonon tulkintana on:

- `c1 c0`: tavu `11000000` kerran
- `c2 00`: tavu `00000000` kahdesti
- `c2 01`: tavu `00000001` kahdesti
- `81`: tavu `10000001` kerran
- `c2 ff`: tavu `11111111` kahdesti

Kuvan ensimmäinen rivi tavujonona on siis seuraava:

`1100000000000000000000000000000100000001100000011111111111111111`

Jokainen bitti vastaa yhtä kuvan pikseliä, ja tämä täsmää yllä olevan kuvan ensimmäiseen riviin (0 = valkoinen, 1 = musta).

### Ohjelman toteutus

Seuraava koodi näyttää, miten ohjelma voidaan toteuttaa:

```c
#include <stdio.h>

struct PCXHeader {
    char signature;
    char version;
    char encoding;
    char bits_per_pixel;
    short min_x;
    short min_y;
    short max_x;
    short max_y;
    short h_res;
    short v_res;
    char palette[48];
    char reserved1;
    char bit_planes;
    short bytes_per_line;
    short palette_type;
    short h_size;
    short v_size;
    char reserved2[54];
};

int main(int argc, char **argv) {
    struct PCXHeader header;

    if (argc != 2) {
        printf("Invalid number of arguments\n");
        return 1;
    }

    FILE *file = fopen(argv[1], "rb");
    if (file == NULL) {
        printf("Can't open the file\n");
        return 1;
    }

    fread(&header, sizeof(header), 1, file);

    if (header.signature == 0x0a) {
        printf("PCX signature found\n");
    } else {
        printf("Invalid PCX file\n");
        return 1;
    }

    int num_bits = header.bits_per_pixel * header.bit_planes;
    if (num_bits != 1) {
        printf("Only monochrome images supported\n");
        return 1;
    }

    int width = header.max_x - header.min_x + 1;
    int height = header.max_y - header.min_y + 1;
    printf("Image width: %d\n", width);
    printf("Image height: %d\n", height);

    int bytes_per_line = header.bytes_per_line;
    printf("Bytes per line: %d\n", bytes_per_line);

    int total_bytes = 0;
    int pixel_count = 0;
    int line_count = 0;
    while (!feof(file)) {
        unsigned char byte;
        fread(&byte, 1, 1, file);

        int len;
        if ((byte & 0xc0) == 0xc0) {
            len = byte ^ 0xc0;
            fread(&byte, 1, 1, file);
        } else {
            len = 1;
        }

        for (int i = 0; i < len; i++) {
            for (int pos = 7; pos >= 0; pos--) {
                if (pixel_count == width) {
                    break;
                }
                if (byte & (1 << pos)) {
                    printf(".");
                } else {
                    printf("@");
                }
                pixel_count++;
            }
            total_bytes++;
            if (total_bytes == bytes_per_line) {
                printf("\n");
                total_bytes = 0;
                pixel_count = 0;
                line_count++;
            }
            if (line_count == height) {
                goto end;
            }
        }
    }
    end:
    fclose(file);
}
```

## Funktion parametrilista

Funktio `printf` on erityinen, koska siinä on vaihteleva  parametrien määrä. Esimerkiksi funktiota voi kutsua `printf("%d", a)` ja `printf("%d %d", a, b)`.

Tällaisen funktion pystyy tekemään myös itse käyttämällä standardikirjaston tiedostossa `stdarg.h` olevia makroja. Seuraavassa on esimerkkinä funktio `my_print`, joka tulostaa tekstiä:

```c
void my_print(char *format, ...) {
    va_list params;
    va_start(params, format);
    for (int i = 0; format[i]; i++) {
        if (format[i] == '@') {
            printf("%d", va_arg(params, int));
        } else {
            printf("%c", format[i]);
        }
    }
    va_end(params);
}
```

Merkkijonossa `format` merkki `@` tarkoittaa, että tämän merkin tilalle tulee `int`-luku funktion parametrilistasta. Kaikki muut merkit tulostetaan sellaisenaan. Esimerkiksi funktiota voi käyttää näin:

```c
int a = 2, b = 3;
my_print("Lukujen @ ja @ summa on @\n", a, b, a + b);
```

Koodin tulostus on seuraava:

```
Lukujen 2 ja 3 summa on 5
```

Funktion parametrilistan käsittely rakentuu seuraavista vaiheista:

- Funktion parametrilistan lopussa on `...`, mikä tarkoittaa vaihtelevaa määrää parametreja.
- Funktion alussa määritellään `va_list`-tyyppinen muuttuja `params`, jonka kautta parametreja käsitellään.
- Makroa `va_start` kutsutaan parametrien käsittelyn aluksi. Makrolle annetaan viittaus funktion viimeiseen pakolliseen parametriin (tässä tapauksessa parametri `format`).
- Makrolla `va_arg` haetaan seuraava parametri funktion parametrilistalta. Makrolle annetaan haettavan parametrin tyyppi (tässä tyyppi on aina `int`).
- Makroa `va_end` kutsutaan parametrien käsittelyn lopuksi.
