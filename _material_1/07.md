# 7. Ohjelmistokehitys

## Koodi tiedostoissa

C-ohjelman koodi muodostuu yleensä useasta tiedostosta, joissa on viittauksia toisiinsa. Esimerkiksi seuraava ohjelma muodostuu kahdesta tiedostosta:

{: .code-title }
main.c
```c
void print_message(char *message);

int main(void) {
    print_message("We get signal.");
    print_message("Main screen turn on.");
}
```

Tiedostossa `main.c` on ohjelman pääfunktio `main`, joka kutsuu muualla määriteltyä funktiota `print_message`. Tiedoston alussa on funktion `print_message` esittely, joka näyttää, miten muualla määriteltyä funktiota voidaan kutsua.

{: .code-title }
message.c
```c
#include <stdio.h>
#include <string.h>

void print_stars(int n) {
    for (int i = 0; i < n; i++) {
        printf("*");
    }
    printf("\n");
}

void print_message(char *message) {
    int n = strlen(message);
    print_stars(n + 4);
    printf("* %s *\n", message);
    print_stars(n + 4);
}
```

Tiedostossa `message.c` on funktion `print_message` määrittely. Funktio kutsuu funktiota `print_stars`, joka on myös määritelty samassa tiedostossa.

<div class="note" markdown="1">
Funktion _esittely_ (_declaration_) kertoo, miten funktiota voidaan kutsua, kun taas funktion _määrittely_ (_definition_) kertoo, mitä funktio tekee, kun sitä kutsutaan.

Esimerkiksi funktion `print_message` esittely

```c
void print_message(char *message);
```

kertoo, että funktiolla ei ole palautusarvoa ja sille tulee antaa yksi parametri, jonka tyyppinä on `char*`. Funktion määrittely

```c
void print_message(char *message) {
    int n = strlen(message);
    print_stars(n + 4);
    printf("* %s *\n", message);
    print_stars(n + 4);
}
```
puolestaan sisältää funktion toteutuksen koodina.
</div>

Ohjelman voi kääntää seuraavalla komennolla:

```console
$ gcc main.c message.c -o main
```

Tässä komennossa annetaan kaksi kooditiedostoa (`main.c` ja `message.c`), jotka käännetään binääritiedostoksi `main`.

Käännöksen jälkeen ohjelman voi suorittaa seuraavasti:

```console
$ ./main
******************
* We get signal. *
******************
************************
* Main screen turn on. *
************************
```

<div class="note" markdown="1">
C-kielessä jokainen kooditiedosto (`.c`) on erillinen _käännösyksikkö_ (_translation unit_), joka käännetään objektitiedostoksi.

Ohjelman käännöksessä kaikki kooditiedostot käännetään ensin objektitiedostoiksi. Tämän jälkeen objektitiedostot linkitetään lopulliseksi suoritettavaksi binääritiedostoksi.

Teimme äsken koko käännöksen samalla komennolla, mutta käännöksen vaiheet on mahdollista tehdä myös erikseen. Seuraavat komennot kääntävät tiedostot `main.c` ja `message.c` objektitiedostoiksi `main.o` ja `message.o`:

```console
$ gcc -c main.c -o main.o
$ gcc -c message.c -o message.o
```

Tämän jälkeen objektitiedostot voidaan linkittää suoritettavaksi ohjelmaksi:

```console
$ gcc main.o message.o -o main
```
</div>

### Näkyvyys ja esittely

C-kielessä tiedostossa määritellyt funktiot ja muuttujat ovat oletuksena näkyvissä koko ohjelman laajuisesti. Toisessa tiedostossa määriteltyä funktiota tai muuttujaa voi käyttää, kunhan se esitellään ennen käyttämistä.

Esimerkiksi seuraavassa tiedostossa `main.c` käytetään funktiota `secret_message` ja muuttujaa `secret_value`, jotka on määritelty tiedostossa `secret.c`.

{: .code-title }
main.c
```c
void secret_message(void);
extern int secret_value;

int main(void) {
    secret_message();
    printf("%d\n", secret_value);
}
```

{: .code-title }
secret.c
```c
#include <stdio.h>

int secret_value = 1337;

void secret_message(void) {
    printf("Main screen turn on.\n")
}
```

Toisessa tiedostossa määritellyn muuttujan esittelyssä tulee käyttää avainsanaa `extern` yllä olevalla tavalla. Avainsanaa `extern` voi käyttää myös toisessa tiedostossa määritellyn funktion yhteydessä. Funktion `secret_message` voisi siis esitellä tiedostossa `main.c` myös seuraavasti:

```c
extern void secret_message(void);
```

Funktion esittelyn kanssa ei usein käytetä avainsanaa `extern`, mutta sitä voi käyttää selventämään, että kyseessä on jossain muualla määritelty funktio.

<div class="note" markdown="1">
Muuttujan esittelyssä avainsana `extern` tarvitaan, koska muuten ei olisi selvää, että kyseessä on muuttujan esittely eikä määrittely. Koodi

```c
int secret_value;
```

määrittelee muuttujan `secret_value`, jonka alkuarvoksi tulee 0.
</div>

Koska funktiot ja muuttujat näkyvät oletuksena kaikkialla, kahdessa tiedostossa ei voi olla samannimisen funktion tai muuttujan määrittelyä. Tässä tulisi ongelmaksi, ettei olisi selvää, kumpaa funktiota tai muuttujaa tulisi käyttää.

### Paikallinen näkyvyys

Avainsana `static` ilmaisee, että funktion tai muuttujan näkyvyys on paikallinen eli sitä voi käyttää vain tiedostossa, jossa se on määritelty.

Esimerkiksi seuraavassa koodissa funktio `print_stars` on määritelty paikalliseksi, mikä on perusteltua, koska kyseessä on funktion `print_message` apufunktio, jota ei ole tarkoitus kutsua muualta.

```c
static void print_stars(int n) {
    for (int i = 0; i < n; i++) {
        printf("*");
    }
    printf("\n");
}

void print_message(char *message) {
    int n = strlen(message);
    print_stars(n + 4);
    printf("* %s *\n", message);
    print_stars(n + 4);
}
```

Kun funktion tai muuttujan määrittelyssä on avainsana `static`, kahdessa tiedostossa voi olla samanniminen funktio tai muuttuja, koska määrittely on paikallinen eikä näy muihin tiedostoihin.

## Projektin rakenne

Tavallinen tapa rakentaa C-kielinen projekti on lisätä kullekin kooditiedostolle (`.c`) otsikkotiedosto (`.h`), joka esimerkiksi esittelee kooditiedoston funktiot, joita voidaan kutsua muista kooditiedostoista. Otsikkotiedosto voidaan ottaa mukaan kooditiedostoissa `#include`-komennon avulla.

Olemme käyttäneet `#include`-komentoa aiemmin standardikirjaston yhteydessä, jolloin otsikkotiedoston nimi annetaan kulmasulkujen `<` ja `>` sisällä. Esimerkiksi seuraava komento ottaa mukaan tiedoston `stdio.h` sisällön:

```c
#include <stdio.h>
```

Projektissa olevien omien otsikkotiedostojen nimet kirjoitetaan puolestaan lainausmerkkien sisään. Esimerkiksi seuraava komento ottaa mukaan tiedoston `message.h` sisällön:

```c
#include "message.h"
```

### Otsikkotiedoston käyttö

Seuraavassa esimerkissä tiedostossa `main.c` määritelty pääfunktio `main` kutsuu funktiota `print_message`. Otsikkotiedosto `message.h` sisältää funktion `print_message` esittelyn, jonka perusteella funktiota voidaan kutsua. Tiedosto `message.c` puolestaan sisältää funktion `print_message` määrittelyn.

{: .code-title }
main.c
```c
#include "message.h"

int main(void) {
    print_message("We get signal.");
    print_message("Main screen turn on.");
}
```

{: .code-title }
message.h
```c
void print_message(char *message);
```

{: .code-title }
message.c
```c
#include "message.h"
#include <stdio.h>
#include <string.h>

static void print_stars(int n) {
    for (int i = 0; i < n; i++) {
        printf("*");
    }
    printf("\n");
}

void print_message(char *message) {
    int n = strlen(message);
    print_stars(n + 4);
    printf("* %s *\n", message);
    print_stars(n + 4);
}
```

Seuraavat komennot kääntävät ja suorittavat ohjelman:

```console
$ gcc main.c message.c -o main
$ ./main
******************
* We get signal. *
******************
************************
* Main screen turn on. *
************************
```

Tässä otsikkotiedoston `message.h` hyötynä on, että kun halutaan käyttää tiedoston `message.c` funktiota, riittää laittaa koodin alkuun `#include`-komento, joka ottaa mukaan otsikkotiedoston `message.h`.

<div class="note" markdown="1">
Itse asiassa tiedostossa `message.c` ei olisi pakko olla riviä

```c
#include "message.h"
```

koska tiedostossa on varsinainen funktion `print_message` määrittely. Kuitenkin on hyvä käytäntö lisätä tämä rivi esimerkiksi sen takia, että kääntäjä varmistaa funktion esittelyn ja määrittelyn yhteensopivuuden.
</div>

### Tietotyyppi otsikkotiedostossa

Otsikkotiedosto voi sisältää funktioiden esittelyjen lisäksi myös esimerkiksi tietotyyppien määrittelyjä. Esimerkiksi seuraava tiedosto `arraylist.h` määrittelee tietotyypin `ArrayList` sekä sitä käsittelevät funktiot:

{: .code-title }
arraylist.h
```c
typedef struct ArrayList ArrayList;

struct ArrayList {
    int size;
    int capacity;
    int *items;
};

ArrayList* array_list_create();
void array_list_insert(ArrayList *list, int value);
void array_list_print(ArrayList *list);
void array_list_free(ArrayList *list);
```

Tiedosto `arraylist.c` puolestaan sisältää yllä olevien funktioiden toteutukset.

Nyt taulukkolistaa voidaan käyttää tiedostossa `main.c` seuraavasti:

{: .code-title }
main.c
```c
#include <stdio.h>
#include "arraylist.h"

int main() {
    ArrayList *list = array_list_create();

    array_list_insert(list, 42);
    array_list_insert(list, 5);
    array_list_insert(list, 1337);

    printf("%d\n", list->items[0]); // 42
    printf("%d\n", list->items[1]); // 5
    printf("%d\n", list->items[2]); // 1337

    array_list_free(list);
}
```

Otsikkotiedoston `arraylist.h` ansiosta tiedostossa `main.c` on käytettävissä taulukkolistan funktiot sekä tietotyypin `ArrayList` rakenne. Jälkimmäistä tarvitaan, kun koodi tulostaa listan alkioiden sisällöt syntaksilla `list->items`.

<div class="note" markdown="1">
Toisaalta voitaisiin haluta, että tietotyypin sisäinen toteutus ei ole ulkopuolisen kooditiedoston saatavilla. Tässä tapauksessa tämä tarkoittaisi, että esimerkiksi syntaksin `list->items` käyttäminen ei ole sallittua `main.c`-tiedostossa.

Tämän voi toteuttaa muuttamalla otsikkotiedostoa `arraylist.h` niin, että tiedostossa on vain `typedef`-määrittely ja varsinainen `struct`-määrittely on tiedostossa `arraylist.c`. Tällöin tiedostossa `main.c` voi kutsua tiedoston `arraylist.c` funktioita kuten ennenkin, mutta ei ole mahdollista viitata tietotyypin `ArrayList` kenttiin.
</div>

### Include-vahti

Hyvä käytäntö on lisätä otsikkotiedostoon include-vahti, joka varmistaa, että otsikkotiedoston sisältö liitetään mukaan enintään kerran. Tavallinen tapa toteuttaa include-vahti on seuraava:

{: .code-title }
arraylist.h
```c
#ifndef ARRAYLIST_H
#define ARRAYLIST_H

typedef struct ArrayList ArrayList;

struct ArrayList {
    int size;
    int capacity;
    int *items;
};

ArrayList* array_list_create();
void array_list_insert(ArrayList *list, int value);
void array_list_print(ArrayList *list);
void array_list_free(ArrayList *list);

#endif // ARRAYLIST_H
```

Tässä direktiivit `#ifndef` ja `#endif` rajaavat koodin, joka liitetään mukaan siinä tapauksessa, ettei nimeä `ARRAYLIST_H` ole määritelty. Tämän koodin alussa direktiivi `#define` määrittelee nimen `ARRAYLIST_H`, minkä seurauksena koodi liitetään mukaan enintään kerran.

<div class="note" markdown="1">
Kommentti `// ARRAYLIST_H` selventää, että direktiivi `#endif` liittyy aiempaan direktiiviin `#ifndef ARRAYLIST_H`. Kuitenkin direktiivi `#endif` toimisi myös ilman tätä kommenttia.
</div>

Tässä tapauksessa include-vahdin hyöty on siinä, että sen ansiosta koodissa ei määritellä useita kertoja `ArrayList`-tietotyyppiä, vaikka komento `#include "arraylist.h"` esiintyisi useita kertoja koodissa. C-kielessä ei ole sallittua määritellä useita kertoja samaa tietotyyppiä.

<div class="note" markdown="1">
Jos otsikkotiedostossa on vain funktioiden esittelyjä, include-vahtia ei sinänsä tarvita, koska saman funktion esitteleminen useita kertoja ei haittaa. Kuitenkin hyvä käytäntö on laittaa include-vahti _kaikkiin_ otsikkotiedostoihin riippumatta tiedostojen tämänhetkisestä sisällöstä.
</div>

## Makefile-työkalu

Makefile on työkalu, jonka avulla voidaan automatisoida C-projektin kääntäminen. Ideana on kuvailla projektin hakemistossa tiedostossa `Makefile`, miten projekti tulee kääntää, minkä jälkeen käännöksen voi tehdä helposti `make`-komennolla.

Tarkastellaan esimerkkinä aiempaa viestejä näyttävää ohjelmaa, joka muodostuu tiedostoista `main.c`, `message.c` ja `message.h`. Voimme tehdä esimerkiksi seuraavan tiedoston `Makefile` projektia varten:

{: .code-title }
Makefile
```make
CC = gcc
CFLAGS = -Wall -Wextra -std=c99

TARGET = main
OBJS = main.o message.o

all: $(TARGET)

$(TARGET): $(OBJS)
	$(CC) $(CFLAGS) $(OBJS) -o $(TARGET)

main.o: main.c message.h
	$(CC) $(CFLAGS) -c main.c

message.o: message.c message.h
	$(CC) $(CFLAGS) -c message.c

clean:
	rm -f $(OBJS) $(TARGET)
```

<div class="note" markdown="1">
Tiedostossa `Makefile` sisentämiseen tulee käyttää tabulaattoria. Jos sisennys tehdään välilyönneillä, tiedostoa ei voida käyttää.
</div>

Voimme nyt kääntää ohjelman komennolla `make`:

```console
$ make
gcc -Wall -Wextra -std=c99 -c main.c
gcc -Wall -Wextra -std=c99 -c message.c
gcc -Wall -Wextra -std=c99 main.o message.o -o main
```

Tässä tapauksessa suoritetaan kolme `gcc`-komentoa, jotka kääntävät kooditiedostot objektitiedostoiksi ja sitten objektitiedostot lopulliseksi ohjelmaksi.

Käännöksen jälkeen ohjelma on valmis suoritettavaksi:

```console
$ ./main
******************
* We get signal. *
******************
************************
* Main screen turn on. *
************************
```

Voimme myös käyttää komentoa `make clean` poistamaan käännöksen aikana muodostetut tiedostot:

```console
$ make clean
rm -f main.o message.o main
```

Tämän jälkeen projektin voisi kääntää uudestaan puhtaalta pöydältä.

### Makefile-tiedosto

Katsotaan nyt tarkemmin, mistä osista äskeinen tiedosto `Makefile` muodostuu. Tiedoston alussa määritellään muuttujia:

```make
CC = gcc
CFLAGS = -Wall -Wextra -std=c99
```

Muuttuja `CC` kertoo käytettävän kääntäjän nimen, ja muuttuja `CFLAGS` sisältää kääntäjälle annettavat parametrit.

```make
TARGET = main
OBJS = main.o message.o
```

Muuttuja `TARGET` kertoo lopullisen ohjelmatiedoston nimen, ja muuttuja `OBJS` sisältää objektitiedostot, joita käännöksessä tarvitaan.

Tämän jälkeen tiedostossa on sääntöjä, jotka määrittelevät, miten halutut tiedostot saadaan aikaan käännösprosessissa.

```make
all: $(TARGET)
```

Tämä sääntö kertoo, että käännöksen oletustavoite on saada aikaan tiedosto `TARGET` eli lopullinen ohjelmatiedosto. Tätä tavoitetta käytetään, kun suoritetaan komento `make` ilman parametreja tai komento `make all`.

```make
$(TARGET): $(OBJS)
	$(CC) $(CFLAGS) $(OBJS) -o $(TARGET)
```

Tämä sääntö tarkoittaa, että kun halutaan tuottaa tiedosto `TARGET`, tarvitaan ensin tiedostot `OBJS`. Kun tiedostot `OBJS` ovat olemassa, voidaan suorittaa toisella rivillä oleva käännöskomento.

```make
main.o: main.c message.h
	$(CC) $(CFLAGS) -c main.c

message.o: message.c message.h
	$(CC) $(CFLAGS) -c message.c
```

Nämä säännöt kertovat, miten objektitiedostot `main.o` ja `message.o` saadaan tuotettua. Esimerkiksi kun halutaan tuottaa tiedosto `main.o`, tarvitaan ensin tiedostot `main.c` ja `message.h`, minkä jälkeen voidaan suorittaa annettu käännöskomento.

```make
clean:
	rm -f $(OBJS) $(TARGET)
```

Tämä sääntö kuvaa, miten komento `make clean` toimii. Komento poistaa kaikki käännöksen aikana tuotetut tiedostot hakemistosta.

<div class="note" markdown="1">
Yleisesti ottaen `Makefile`-tiedoston sääntö on seuraavaa muotoa:
```make
target: dependencies
	command
```
Tulkintana on, että kun halutaan tuottaa `target`, tarvitaan ensin tiedostot `dependencies` ja sitten suoritetaan komento `command`.

Tässä `target` voi olla joko tiedoston nimi (kuten `main.o`) tai muu nimetty tavoite, joka ei ole tiedosto (kuten `clean`).

Jos `dependencies` on tyhjä, tavoitetta varten ei tarvitse olla olemassa mitään tiedostoja. Jos `command` on tyhjä, ei suoriteta mitään komentoa.
</div>

### Tiedostojen riippuvuudet

Makefilen yhtenä hyötynä on, että komento `make` ottaa huomioon tiedostojen riippuvuudet ja suorittaa käännöskomennon vain, jos jokin käännettävä tiedosto on muuttunut edellisen käännöksen jälkeen.

Esimerkiksi jos koko projekti on jo käännetty uusimmilla tiedostoilla, `make` ei tee mitään vaan antaa seuraavan viestin:

```console
$ make
make: Nothing to be done for 'all'.
```

Seuraavassa tilanteessa projektia on muutettu niin, että tiedoston `main.c` sisältö on muuttunut. Nyt käännös etenee näin:

```console
$ make
gcc -Wall -Wextra -std=c99 -c main.c
gcc -Wall -Wextra -std=c99 main.o message.o -o main
```

Tässä riittää kääntää tiedosto `main.c` objektitiedostoksi `main.o` ja suorittaa sitten lopullinen käännöskomento. Koska tiedosto `message.c` ei ole muuttunut, aiemmin tuotettu `message.o` kelpaa edelleen eikä sitä tarvitse kääntää uudestaan.

Tämä on erityisen hyödyllistä suurissa projekteissa, joissa on paljon käännettäviä tiedostoja. Projektin käännösaika on pienempi, kun ei tarvitse kääntää kaikkia tiedostoja uudestaan vaan vain muuttuneet tiedostot.

## Ulkoiset kirjastot

Luvussa 1 teimme esimerkkiohjelman, joka laskee annetun luvun kertoman:

```c
#include <stdio.h>

int main(void) {
    printf("Anna luku: ");
    int number;
    scanf("%d", &number);

    long factorial = 1;
    for (int x = 1; x <= number; x++) {
        factorial *= x;
    }

    printf("Luvun %d kertoma on %ld\n", number, factorial);
}
```

Tämän ohjelman rajoituksena on, ettei sillä voi laskea kovin suurta kertomaa, koska C:n lukutyypit ovat rajoitetun kokoisia. Esimerkiksi tyyppi `long` on tavallisesti 64-bittinen, minkä takia siihen mahtuu enintään luvun 20 kertoma:

```console
Anna luku: 20
Luvun 20 kertoma on 2432902008176640000
```

Luvun 21 kertomaksi tulee negatiivinen tulos merkkinä siitä, että luku on pyörähtänyt ympäri ylivuodon seurauksena:

```console
Anna luku: 21
Luvun 21 kertoma on -4249290049419214848
```

C-kielen standardikirjastossa ei ole tapaa käsitellä suuria kokonaislukuja, mutta voimme käyttää tähän ulkoista GMP-kirjastoa (_GNU Multiple Precision Arithmetic Library_), jolla pystyy käsittelemään mielivaltaisen suuria kokonaislukuja.

### Kirjaston asennus ja käyttö

Ensimmäinen vaihe ulkoisen GMP-kirjaston käyttämisessä on asentaa kirjasto kehitysympäristöön. Esimerkiksi Ubuntussa voimme asentaa paketin `libgmp-dev` seuraavasti:

```console
$ sudo apt install libgmp-dev
```

Tämä komento asentaa järjestelmään tarvittavat tiedostot, jotta voimme käyttää ohjelmassa GMP-kirjaston otsikkotiedostoa `gmp.h` sekä liittää kirjaston mukaan ohjelman käännöksessä.

Seuraavassa on uusi toteutus kertoman laskevasta ohjelmasta käyttäen GMP-kirjastoa. Tässä toteutuksessa tuloksen suuruutta ei ole rajoitettu, vaan ohjelmalla voi laskea hyvin suurenkin kertoman.

```c
#include <stdio.h>
#include <gmp.h>

int main(void) {
    printf("Anna luku: ");
    int number;
    scanf("%d", &number);

    mpz_t factorial;
    mpz_init(factorial);
    mpz_set_ui(factorial, 1);

    for (int x = 1; x <= number; x++) {
        mpz_mul_ui(factorial, factorial, x);
    }

    gmp_printf("Luvun %d kertoma on %Zd\n", number, factorial);
}
```

Ohjelma määrittelee `mpz_t`-tyyppisen muuttujan `factorial`, johon voidaan tallentaa mielivaltaisen suuri kokonaisluku. Tämän jälkeen ohjelma laskee kertoman `mpz`-funktioilla ja lopuksi tulostaa tuloksen `gmp_printf`-funktiolla.

Seuraava komento kääntää ohjelman:

```console
$ gcc factorial.c -o factorial -lgmp
```

Komennossa on mukana parametri `-lgmp`, jonka ansiosta GMP-kirjasto linkitetään mukaan käännöksessä.

Tämän jälkeen ohjelman voi suorittaa seuraavasti:

```console
Anna luku: 100
Luvun 100 kertoma on 93326215443944152681699238856266700490715968264381621468592963895217599993229915608941463976156518286253697920827223758251185210916864000000000000000000000000
```

<div class="note" markdown="1">
Itse asiassa GMP-kirjastossa on myös suorempi tapa laskea luvun kertoma käyttäen valmista funktiota `mpz_fac_ui` seuraavasti:

```c
#include <stdio.h>
#include <gmp.h>

int main(void) {
    printf("Anna luku: ");
    int number;
    scanf("%d", &number);

    mpz_t factorial;
    mpz_init(factorial);
    mpz_fac_ui(factorial, number);

    gmp_printf("Luvun %d kertoma on %Zd\n", number, factorial);
}
```
</div>

### Kirjasto järjestelmässä

Kun GMP-kirjasto asennetaan Linux-järjestelmään, tiettyihin järjestelmän hakemistoihin sijoitetaan kirjastoon liittyviä tiedostoja. Esimerkiksi Ubuntussa kirjaston asentaminen voisi lisätä järjestelmään seuraavat tiedostot:

- `/usr/include/x86_64-linux-gnu/gmp.h`: otsikkotiedosto
- `/usr/lib/x86_64-linux-gnu/libgmp.a`: staattinen kirjastotiedosto
- `/usr/lib/x86_64-linux-gnu/libgmp.so`: dynaaminen kirjastotiedosto

Tiedostot on sijoitettu järjestelmässä hakemistoihin, joista kääntäjä etsii niitä. Kun koodissa on direktiivi `#include <gmp.h>`, kääntäjä etsii tiedostoa `gmp.h` hakemistosta `/usr/include`. Kun käännöskomennossa on parametri `-lgmp`, kääntäjä olettaa tämän viittaavan `libgmp.so`-tiedostoon hakemistossa `/usr/lib`.

Oletuksena kirjasto linkitetään ohjelmaan dynaamisesti, jolloin käännetyn ohjelman osaksi ei tule kirjaston koodia. Ohjelma vaatii toimiakseen järjestelmässä olevan tiedoston `libgmp.so`, jota käytetään ohjelman suoritusvaiheessa.

Dynaamisen linkityksen etuna on, että kirjaston käyttäminen ei kasvata ohjelmatiedoston kokoa, vaan kaikki GMP-kirjastoa käyttävät ohjelmat voivat käyttää yhteisesti tiedostoa `libgmp.so`. Jos kirjasto päivitetään järjestelmässä, päivitys vaikuttaa automaattisesti kaikkiin ohjelmiin. Toisaalta ohjelmaa ei voi käyttää, jos järjestelmässä ei ole tiedostoa `libgmp.so`.

<div class="note" markdown="1">
Seuraava komento näyttää dynaamisesti linkitetyt kirjastot, jotka ohjelma tarvitsee käynnistyäkseen:

```console
$ objdump -p factorial | grep NEEDED
  NEEDED               libgmp.so.10
  NEEDED               libc.so.6
```

Tässä tapauksessa ohjelma tarvitsee kaksi kirjastoa: GMP-kirjaston (`libgmp.so`) sekä C-standardikirjaston (`libc.so`).
</div>

Dynaamisen linkityksen vaihtoehtona on staattinen linkitys, jolloin käytetään tiedostoa `libgmp.a` ja kirjaston koodi tulee ohjelman osaksi. Seuraava komento kääntää ohjelman niin, että GMP-kirjasto linkitetään staattisesti:

```console
$ gcc factorial.c -o factorial -l:libgmp.a
```

Kun GMP-kirjasto on linkitetty staattisesti, ohjelmaa voi käyttää ilman järjestelmässä olevaa GMP-kirjastoa, mutta ohjelmatiedoston koko on suurempi.

<div class="note" markdown="1">
Kurssin opettajan järjestelmässä ohjelmatiedosto `factorial` vie tilaa 16208 tavua GMP-kirjaston dynaamisella linkityksellä ja 179528 tavua staattisella linkityksellä. Ohjelmatiedosto vie siis yli 10-kertaisesti tilaa, kun käytetään staattista linkitystä dynaamisen linkityksen sijasta.
</div>
