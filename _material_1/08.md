# 8. Käännösprosessi

{: .code-title }
collatz.c
```c
#include <stdio.h>

int main(void) {
    long n;
    printf("Anna luku: ");
    scanf("%ld", &n);

    while (1) {
        printf("%ld ", n);

        if (n == 1) break;

        if (n % 2 == 0) {
            n = n / 2;
        } else {
            n = 3 * n + 1;
        }
    }
    printf("\n");
}
```

```console
Anna luku: 14
14 7 22 11 34 17 52 26 13 40 20 10 5 16 8 4 2 1
```

```console
$ gcc -save-temps collatz.c -o collatz
```
## Esikääntäjän käsittely

Käännöksen ensimmäisessä vaiheessa esikääntäjä käy läpi kooditiedoston. Esikääntäjä käsittelee koodissa olevat `#`-alkuiset direktiivit sekä tekee mahdollisesti joitakin muita muutoksia, kuten poistaa koodissa olevat kommentit.

Ohjelmamme käännöksessä esikääntäjä käsittelee direktiivin `#include <stdio.h>`, joka liittää mukaan standardikirjaston otsikkotiedoston `stdio.h`. Tämä tuo koodin alkuun suuren määrän rivejä, joissa on esimerkiksi standardikirjaston tietotyyppien määrittelyjä ja funktioiden esittelyjä.

Seuraavassa on näytteitä tiedostosta `collatz.i`, joka sisältää kooditiedoston esikääntäjän käsittelyn jälkeen:

{: .code-title }
collatz.i
```c

```

Tässä tapauksessa tiedostossa `stdio.h` on lisää `#include`-direktiivejä, jotka liittävät mukaan muita tiedostoja. Esimerkiksi tiedostossa on rivit `#include <stddef.h>` ja `#include <stdarg.h>`. Esikääntäjä käsittelee kaikki direktiivit samalla kertaa niin, ettei tuloksena olevassa koodissa enää viitata muihin tiedostoihin.

Esikääntäjän tuottamassa koodissa `#`-rivit ilmaisevat, että tietyt koodirivit on haettu tietyn tiedoston tietyltä riviltä. Esimerkiksi

```c
# 214 "/usr/lib/gcc/x86_64-linux-gnu/13/include/stddef.h" 3 4
typedef long unsigned int size_t;
```

tarkoittaa, että `typedef`-määrittely on haettu tiedostosta `stddef.h` riviltä 214. Tämä rivi määrittelee, että tyyppi `size_t` tarkoittaa samaa kuin `long unsigned int`. Näiden rivien ansiosta kääntäjä tietää käännöksen myöhemmässä vaiheessa, mistä tiedostosta mikäkin koodirivi on tullut.

Esikääntäjä ei päättele, mitä osia tiedostosta `stdio.h` todella tarvitaan käännöksessä, vaan se liittää mukaan tiedoston koko sisällön. Tässä tapauksessa funktion `printf` esittely on oleellinen, koska koodi kutsuu tätä funktiota, mutta
funktioiden `fprintf` ja `sprintf` esittelyjä ei tarvittaisi, koska koodi ei kutsu näitä funktioita.

## Käännös assemblyksi

Käännöksen seuraavassa vaiheessa koodi käännetään assemblyksi eli symboliselle konekielelle. Tämä on käännöksen oleellinen vaihe, koska kääntäjän tulee muuttaa C-kielinen koodi vastaavaksi konekieliseksi koodiksi.

Tutustumme konekieliseen ohjelmointiin tarkemmin myöhemmin kurssilla, mutta voimme tarkastella jo tässä vaiheessa joitakin asioita konekielisessä koodissa. Tästä saa kiinnostavaa tietoa siitä, mitä kääntäjä tekee muuttaessaan C-kielistä koodia konekieliseksi koodiksi.

### Merkkijonoliteraalit

```nasm
	.section	.rodata
.LC0:
	.string	"Anna luku: "
.LC1:
	.string	"%ld"
.LC2:
	.string	"%ld "
```

Koodin alussa on osio `.rodata`, jossa määritellään koodissa käytettävät merkkijonoliteraalit. Osion nimi viittaa sanoihin _read only_, eli nämä merkkijonot voidaan tallentaa muistissa alueelle, jota ei pysty muuttamaan.

### Tekstin tulostaminen

```nasm
	leaq	.LC0(%rip), %rax
	movq	%rax, %rdi
	movl	$0, %eax
	call	printf@PLT
```

Tämä koodi vastaa seuraavaa C-koodin riviä:

```c
printf("Anna luku: ");
```

Koodi muodostaa funktiolle `printf` annettavat parametrit ja kutsuu sitten funktiota. Koodi muodostuu seuraavista komennoista:

- Komento `leaq .LC0(%rip), %rax` sijoittaa rekisteriin `%rax` nimiön `.LC0` muistiosoitteen eli merkkijonon `"Anna luku: "` muistiosoitteen.
- Komento `movq %rax, %rdi` kopioi muistiosoitteen rekisteristä `%rax` rekisteriin `%rdi`. Linuxissa on käytäntönä, että funktion ensimmäinen parametri annetaan rekisterissä `%rdi`.
- Komento `movl $0, %eax` sijoittaa rekisteriin `%eax` luvun 0. Tämä tarkoittaa, ettei funktion `printf` kutsussa käytetä liukulukuparametreja.
- Komento `call printf@PLT` kutsuu funktiota `printf`. Merkintä `PLT` tarkoittaa, että kyseessä on dynaamisesti linkitetty funktio.

### Luvun kysyminen käyttäjältä

```nasm
	leaq	-16(%rbp), %rax
	movq	%rax, %rsi
	leaq	.LC1(%rip), %rax
	movq	%rax, %rdi
	movl	$0, %eax
	call	__isoc99_scanf@PLT
```

Tämä koodi vastaa seuraavaa C-koodin riviä:

```c
scanf("%ld", &n);
```

Koodi muodostaa funktiolle `scanf` annettavat parametrit ja kutsuu sitten funktiota. Koodi muodostuu seuraavista komennoista:

- Komento `leaq -16(%rbp), %rax` sijoittaa rekisteriin `%rax` muistiosoitteen, joka viittaa pinoon kohtaan, johon on tallennettu muuttujan `n` arvo.
- Komento `movq %rax, %rsi` kopioi muistiosoitteen rekisteristä `%rax` rekisteriin `%rsi`. Linuxissa on käytäntönä, että funktion toinen parametri annetaan rekisterissä `%rsi`.
- Komennot `leaq .LC1(%rip), %rax` ja `movq	%rax, %rdi` kopioivat merkkijonon `"%ld"` muistiosoitteen rekisteriin `%rdi%`, kuten `printf`-kutsussa.
- Komento `movl $0, %eax` ilmaisee, ettei funktion `scanf` kutsussa käytetä liukulukuparametreja.
- Komento `call __isoc99_scanf@PLT` kutsuu funktion `scanf` versiota, joka on C99-standardin mukainen.

### Vertailu ja hyppy

```nasm
	movq	-16(%rbp), %rax
	cmpq	$1, %rax
	je	.L10
```

Tämä koodi vastaa seuraavaa C-koodin riviä:

```c
if (n == 1) break;
```

Koodi muodostuu seuraavista komennoista:

- Komento `movq -16(%rbp), %rax` kopioi pinossa olevan muuttujan `n` arvon rekisteriin `%rax`.
- Komento `cmpq $1, %rax` vertailee lukua 1 ja rekisterin `%rax` arvoa. Vertailun tulos tallentuu sille varattuun rekisteriin prosessorissa, ja tulosta voidaan käyttää myöhemmin koodissa.
- Komento `je .L10` siirtää koodin suorituksen nimiöön `.L10`, jos aiemmin tehdyn vertailun tuloksena on, että arvot ovat yhtä suuret. Muussa tapauksessa koodin suoritus jatkuu seuraavalta riviltä.

### Luvun parillisuuden testaus

```nasm
	movq	-16(%rbp), %rax
	andl	$1, %eax
	testq	%rax, %rax
	jne	.L4
```

Tämä koodi vastaa seuraavaa C-koodin riviä:

```c
if (n % 2 == 0) {
```

Koodi muodostuu seuraavista komennoista:

- Komento `movq -16(%rbp), %rax` kopioi pinossa olevan muuttujan `n` arvon rekisteriin `%rax`.
- Komento `andl $1, %eax` suorittaa and-operaation, jonka vaikutuksesta rekisteriin `%rax` jää vain luvun viimeisen bitin sisältö. Luvun viimeinen bitti ilmaisee, onko luku parillinen (0) vai pariton (1).
- Komento `testq %rax, %rax` suorittaa vertailun, jonka tuloksena saadaan tietää, onko rekisterin `%rax` arvo nolla.
- Komento `jne .L4` siirtää koodin suorituksen nimiöön `.L4`, jos edellisen vertailun vastaus on kieltävä eli luku on pariton.

<div class="note" markdown="1">
Tässä kääntäjä on huomannut, että ehto `n % 2 == 0` testaa luvun parillisuutta, mikä voidaan toteuttaa tehokkaasti and-operaation avulla. Tässä voi ajatella, että ehto `n % 2 == 0` on korvattu käännöksessä ehdolla `(n & 1) == 0`.

Ehdon `n % 3 == 0` tarkastaminen olisi vaikeampaa, koska jaollisuutta kolmella ei voi tutkia yksinkertaisesti luvun bittiesityksestä. Tällöin konekielitasolla täytyisi ehkä todella suorittaa jakolasku yksinkertaisen bittioperaation sijasta.

Kääntäjällä on vapaus tehdä koodiin tämän tyylisiä optimointeja, kunhan käännetty koodi antaa saman tuloksen kuin alkuperäinen koodi. Koodin tuloksen kannalta ei ole merkityksellistä, millä tavalla parillisuus tarkastetaan.
</div>

### Laskutoimitus

```nasm
.L4:
	movq	-16(%rbp), %rdx
	movq	%rdx, %rax
	addq	%rax, %rax
	addq	%rdx, %rax
	addq	$1, %rax
	movq	%rax, -16(%rbp)
```

Tämä koodi vastaa seuraavaa C-koodin riviä:

```c
n = 3 * n + 1;
```

Koodi suoritetaan nimiössä `.L4`, jonne hypätään muuttujan `n` arvon ollessa pariton. Koodi muodostuu seuraavista komennoista:

- Komennot `movq -16(%rbp), %rdx` ja `movq %rdx, %rax` siirtävät muuttujan `n` arvon pinosta rekisterin `%rdx` kautta rekisteriin `%rax`.
- Komento `addq %rax, %rax` kasvattaa rekisterin `%rax` arvoa itsellään.
- Komento `addq %rdx, %rax` lisää rekisterin `%rax` arvoon rekisterin `%rdx` arvon.
- Komento `addq $1, %rax` kasvattaa rekisterin `%rax` arvoa yhdellä.
- Komento `movq	%rax, -16(%rbp)` siirtää rekisterin `%rax` arvon takaisin pinoon muuttujan `n` arvoksi.

Koska konekielessä ei voi suorittaa laskulausekkeita, laskut tulee toteuttaa osissa askel kerrallaan. Tämä konekielinen koodi vastaa seuraavaa C-koodia:

```
d = n;
a = d;
a = a + a;
a = a + d;
a = a + 1;
n = a;
```

<div class="note" markdown="1">
Kääntäjä on taas toteuttanut konekielisen koodin eri logiikalla kuin alkuperäisen koodin. C-koodissa on kertolasku `3 * n`, mutta konekielisessä koodissa tämä on toteutettu yhteenlaskuna `n + n + n`.

Tällainen muutos on mahdollinen, koska laskuna on `3 * n` eli luku `n` kerrotaan aina kolmella. Tämän takia lasku voidaan esittää aina kiinteässä muodossa, jossa lasketaan yhteen kolme kertaa sama luku. Jos laskuna olisi yleisempi `a * n`, vastaavaa muutosta yhteenlaskuksi ei voisi tehdä.

Kertolaskun esittäminen yhteenlaskuna voi olla konekielen kannalta järkevää, koska yhteenlasku on yksinkertaisempi operaatio kuin kertolasku.
</div>

### Merkin tulostaminen

```nasm
.L10:
	nop
	movl	$10, %edi
	call	putchar@PLT
```

Tämä koodi vastaa seuraavaa C-koodin riviä:

```c
printf("\n");
```

Tämä koodi suoritetaan nimiössä `.L10`, jonne hypätään, jos ehto `n == 1` toteutuu eli on aika lopettaa silmukka. Koodi muodostuu seuraavista komennoista:

- Komento `nop` ei tee mitään. Jostain syystä kääntäjä on päätynyt siihen, että tämä komento kannattaa suorittaa tässä kohdassa.
- Komento `movl $10, %edi` siirtää luvun 10 rekisteriin `%edi`. Tämä on osa rekisteriä `%rdi`, jossa on funktiokutsun ensimmäinen parametri. Luku 10 on rivinvaihdon `\n` merkkikoodi.
- Komento `call putchar@PLT` kutsuu standardikirjaston funktiota `putchar`, joka tulostaa yksittäisen merkin eli tässä tapauksessa rivinvaihdon.

Tässä kääntäjä on _muuttanut_ koodissa kutsuttavaa funktiota. C-koodissa kutsutaan funktiota `printf`, mutta konekielisessä koodissa kutsutaan funktiota `putchar`. Kääntäjä on havainnut, että funktiolla `printf` tulostetaan vain yksittäinen merkki, minkä voi tehdä tehokkaammin funktiolla `putchar`.

Kääntäjä voi tehdä tällaisen muutoksen koodiin, koska funktio `printf` on standardikirjaston funktio ja kääntäjä tietää, miten tämä funktio toimii. Tässä tilanteessa funktion `putchar` kutsuminen tuottaa saman tuloksen tehokkaammin kuin funktion `printf` kutsuminen.
